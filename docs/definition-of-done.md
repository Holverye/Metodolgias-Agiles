# Definition of Done y preparación

## Para documentos

- El archivo está en Markdown, tiene título y puede leerse en la vista previa.
- Identificadores, dependencias, roles y cifras coinciden entre documentos.
- Cada historia incluye usuario, necesidad, beneficio y criterios verificables.
- Las fuentes y las decisiones propuestas están diferenciadas.
- Otro integrante revisa el contenido antes de integrarlo al repositorio.
- El cambio se registra con un commit concreto cuando el equipo lo incorpora.

La revisión grupal y los commits permanecen pendientes en la entrega real. Los resultados del Sprint 1 describen un escenario académico.

## Para historias de software en sprints posteriores

- Se cumplen todos los criterios de aceptación.
- El código HTML, CSS y JavaScript está integrado y permite demostrar la función.
- Se verifican manualmente casos válidos, vacíos e inválidos de la historia.
- La pantalla se revisa a 360 px y 1366 px sin contenido cortado.
- No hay errores de JavaScript durante el flujo probado.
- Otro Developer revisa el cambio y se actualiza la documentación.
- El cambio está versionado y el Product Owner revisa su resultado en la Sprint Review.

No se considera Done una historia solo porque esté documentada o tenga una pantalla incompleta.

## Preparación para seleccionar una historia

Debe tener criterios claros, dependencias identificadas, datos de ejemplo acordados y tamaño que el equipo considere viable. Este acuerdo de preparación ayuda a planificar; no sustituye la Definition of Done.
